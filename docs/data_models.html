Путь данных: от API до дашборда

Раз в час Airflow запускает три задачи по очереди. collect_to_stg забирает у USGS новые и изменённые события и кладёт ответ как есть. stg_to_dds разбирает JSON, чистит данные и ведёт историю версий. dds_to_cdm пересобирает витрины. Metabase подключён под пользователем bi_reader, который видит только схему cdm.

Сырой слой (STG): ответы API без изменений

Каждая загрузка — строка в batches, её ключ — идентификатор запуска Airflow, поэтому повтор того же запуска ничего не дублирует. В api_responses лежит весь ответ API, в earthquake_raw — каждое событие отдельно, в исходном GeoJSON. Номер строки id служит отметкой (watermark): детальный слой забирает только строки с номером больше обработанного.

Детальный слой (DDS): события и история их версий

Главная таблица — event_versions. Когда USGS меняет магнитуду, статус, глубину или координаты, старая версия закрывается (заполняется valid_to), а новая открывается; у текущей valid_to пуст и is_current = true. Если поменялось только служебное поле updated, новой версии нет — это проверяет row_hash. База сама гарантирует одну текущую версию на событие (уникальный индекс) и непересекающиеся интервалы (EXCLUDE USING gist). Внизу — отметка обработанных строк STG, журнал загрузок и отбракованные записи с причиной.

Витрины (CDM): готовые таблицы для дашбордов

Верхний ряд — одна строка на землетрясение: event_map для карты и таблиц, revision_summary — первая и текущая версия, event_history — вся цепочка версий для дашборда «История события». Нижний ряд — заранее посчитанные агрегаты: по дням, по возрасту события и по часам наблюдения (машина времени по SCD2). Счётчики считаются только по текущим версиям и только для earthquake; пустая магнитуда — отдельный класс «нет данных». Все витрины пересобираются целиком в одной транзакции: повторный запуск даёт то же самое, ошибка оставляет прежние данные.

Как детальный слой питает витрины

Загрузчик витрин sql/cdm_load.sql читает только схему dds — в сырые данные он не заглядывает, это проверяет автотест. Текущие версии дают счётчики и карту, все версии — уточнения, историю и часовые срезы.

Как витрины питают дашборды

Дашборды собираются скриптом scripts/setup_metabase.py: 30 карточек, 4 вкладки основного дашборда и отдельный дашборд истории события. Фильтры дата, магнитуда, сеть и глубина действуют на все вкладки; клик по event_id открывает историю версий.
